Use Claude Code on your Mac from your phone

Claude Code runs in a terminal, so any way of opening a terminal on your Mac works from a phone. The first thing you will hit is that it asks you to log in again. Here is why, and what fixes it.

The setup

You need a Mac that stays awake and a way to reach it. See keeping a Mac awake and SSH from Android. Once you have a terminal on the Mac, run claude as you would at your desk.

The problem: “please log in”

Claude Code keeps its login in the macOS Keychain. A login over SSH is not part of your desktop session, so it cannot open that Keychain. In our testing, claude started from the phone asked us to log in even though it was signed in at the Mac. Unlocking the Keychain from the command line did not work for us, because the Keychain password differed from the login password.

The fix: attach to a session that lives on your desktop

Programs started from the logged-in desktop session inherit the unlocked Keychain. The trick is to run tmux there and attach to it from the phone, so you join a session that already has access. You can check where a process lives with:

launchctl managername

Inside a session that works, this prints Aqua. A session that prints Background is the one that cannot see your Keychain. We found that the tmux server has to be started as a child of an app running in the desktop session, because a normally daemonised one drifts into Background.

What we verified. We confirmed this with the tmux session that Remote Wake starts, and that claude then started with no login prompt. We have not tested every setup, so treat the manual route as a starting point.

Bonus: it survives dropped connections

Because the session lives on the Mac, a lost phone connection does not stop Claude Code. Reconnect and you land in the same session.

Want the short version?

Remote Wake starts that desktop tmux session for you. Phone sessions are always on, so Claude Code and other tools that rely on your Keychain just work, and a dropped connection puts you back where you were.
