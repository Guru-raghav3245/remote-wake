### Android app prototype (31 Oct 2026, emulator) — engine feasibility PROVEN in the emulator
Question: can a phone app embed the Tailscale engine (no VpnService, no root) and SSH into the Mac? Answer on the emulator: YES.
- `android-proto/main.go`: Go program (tsnet + golang.org/x/crypto/ssh, auth "none" because Tailscale SSH identifies by tailnet identity). Run on the Mac AND as a plain `GOOS=android GOARCH=arm64 CGO_ENABLED=0` executable in the emulator via adb: joined the tailnet and ran `id -un; hostname` on the Mac over SSH in 106 ms (Mac) and 187 ms (emulator). Login is a URL printed by tsnet that the user approves in a browser (or `TS_AUTHKEY`).
- `android-proto/engine/engine.go`: the same as a C-API shared library (`rw_start`, `rw_state`, `rw_exec`, `rw_free`), built with the NDK by `android-app/build-engine.sh` into `android-app/android/app/src/main/jniLibs/arm64-v8a/libtsengine.so` (22 MB, gitignored). Two fixes were needed to run INSIDE a real Android app (the adb-shell run hid both): (1) Android 11+ denies apps netlink, so `net.Interfaces` fails with `route ip+net: netlinkrib: permission denied`; fixed with `netmon.RegisterInterfaceGetter` returning a fake `lo` + `wlan0` (the same hook Tailscale's own Android app uses; one IPv4 address found by connecting a UDP socket, no IPv6); (2) no HOME/XDG_CACHE_HOME, Tailscale's log policy panics "no safe place found to store log state"; fixed by pointing both at the app's state dir.
- `android-app/`: Flutter app (Android only, package `com.guru.remote_wake_app`, flutter at `~/flutter`). `lib/engine.dart` = dart:ffi bridge (blocking Go calls run in `Isolate.run`), `lib/main.dart` = prototype screen: Tailscale state/IP, "Sign in to Tailscale" button, host/user/command fields, Run, output. ### Reconnect on drop + Tailscale SSH "check" approval (2 Nov 2026, emulator) — built, committed
- Engine (`android-proto/engine/engine.go`): SSH keepalive every 5 s (a silent dead network is noticed in about 15 to 25 s), `rw_shell_dropped` (connection lost vs a typed `exit`, from `sess.Wait()`), 3-minute handshake deadline in `rw_shell_open` (was none), `rw_last_banner` (the server's SSH banner).
- App (`lib/terminal_page.dart`): on a drop, a "Connection lost, reconnecting..." banner, retries after 2/4/8/15 s (10 tries, then a Retry button), opens a NEW shell and prints "[reconnected: new shell, earlier programs were stopped]". A reconnect cannot resume running programs (plain SSH); use tmux on the Mac if that matters. A typed `exit` ends the session without retrying.
- Emulator test (release APK): ping running, Wi-Fi + mobile data off, banner within about 25 s, network back, new shell in about 20 ms. With only Wi-Fi off the session survives on the emulator's 3G (no drop), same as the real phone.
- FOUND: the Mac's Tailscale SSH rule is `holdAndDelegate` ("check" mode): about every 12 hours a connection from a phone node hangs until the user approves a link in a browser. The link arrives as the SSH banner; the old app discarded it, so it looked like an endless "connecting..." (seen on the emulator AND the real phone on 2 Nov, a day after it worked). The app now shows "Tailscale needs you to approve this connection" with an Approve button that opens the link (prints `APPROVEURL` to logcat for tests; on the emulator open it on the Mac with `open <url>`). Only a NEW link triggers the banner (`seenUrl`). To avoid the 12-hour prompt the tailnet policy would need SSH action "accept" instead of "check" (admin console, user's decision; weaker security).
- Mistake to avoid: my first deadline edit landed in `rw_exec`, not `rw_shell_open`, because `str.replace` hit the first match; check `git diff` after scripted edits.
- NOT tested on the real phone: reconnect, the Approve button with a real signed-in browser. The release APK in `~/Downloads/RemoteWake.apk` has all of this; the phone was not connected over USB when built, so reinstall it (`adb install -r`).
